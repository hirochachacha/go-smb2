未実装機能の優先順位
調査日: 2026-09-12

汎用クライアントとしての用途、確認できた需要、実装コストをもとにした
順位。工数は相対評価。性能改善効果は未計測。

1. [ ] DFS紹介先の解決・追従
   価値: Active DirectoryのDFS名前空間を実パスを知らずに利用できる。
         go-smb2 issue #69とrclone issue #6942に実際の要望がある。
   現状: DFS関連の定数のみ。紹介先の取得・解析、キャッシュ、対象サーバー
         への再接続、パスの置換が未実装。
   範囲: FSCTL_DFS_GET_REFERRALS、紹介先の選択と期限管理、循環防止、
         別サーバー用の接続・認証方法を渡すAPI。
   工数: 大
   関連: client.go（Mount）, tree_conn.go, internal/smb2/fscc.go

2. [ ] SMB 3.1.1のAES-256-GCM／AES-256-CCM
   価値: AES-256を必須にしたWindows 11／Windows Server 2022以降の
         環境と接続できる。既存の暗号化処理を拡張でき、範囲が比較的小さい。
   現状: AES-128-GCMとAES-128-CCMのみ提示・処理する。
   範囲: 暗号ID、256-bit KDF出力、ネゴシエーション、暗号化・復号、
         WindowsとSambaを使った相互運用テスト。
   工数: 小〜中
   関連: feature.go, conn.go, session.go, kdf.go, internal/smb2/const.go

3. [ ] 大容量転送のパイプライン化
   価値: 高遅延回線でのアップロード・ダウンロードを高速化できる可能性が
         ある。
   現状: 単一のReadAt／WriteAt内ではチャンクを逐次処理する。過去の単純な
         並列化は部分失敗時の正しさを保てず、逐次処理へ戻した。
   着手条件: 実サーバーと遅延を加えた環境で、逐次処理がボトルネックだと
             ベンチマークで確認する。
   注意: クレジット制御、順序どおりの結果確定、部分成功、キャンセル時の
         バッファ寿命を扱う。個別要求のキャンセルで共有接続を閉じない。
   工数: 中〜大
   関連: client.go（readAt, writeAt, ReadFrom, WriteTo）, credit.go

4. [ ] Lease／Oplockとキャッシュ
   価値: 同じファイルへの反復アクセスで通信を削減する。
   現状: CREATEはSMB2_OPLOCK_LEVEL_NONE固定。サーバーから届く非同期の
         OPLOCK_BREAKを処理する仕組みもない。
   範囲: CREATE context、Lease状態、break通知の振り分けとACK、
         キャッシュ無効化。まずキャッシュ対象と整合性規則を決める。
   工数: 大
   関連: request.go（create）, client.go（OpenFile）, conn.go

5. [ ] Durable Handleによる切断復旧
   価値: 一時的なネットワーク断から開いたファイルを復旧する。
   現状: 再接続機構がない。
   依存: Lease／Oplockと再接続可能なDial APIを先に設計する。
   注意: 接続とセッションの再生成、ハンドルの復元、実行結果不明の要求を
         呼び出し側へ伝える必要がある。
   工数: 特大
   関連: conn.go, session.go, client.go

着手方針
- 次の主要機能は、利用要望が確認できるDFS対応を優先する。
- 小さめの範囲で現行Windowsとの互換性を上げるならAES-256を先に行う。
- パイプライン化はベンチマークで効果を確認してから設計する。
- LeaseとDurable Handleは依存範囲が大きいため、具体的な利用要件が出てから
  着手する。

現時点では優先しないもの
- SMB Multichannel、SMB Direct: 複数接続のSession Bindingや経路選択まで
  必要で、汎用クライアントに対する実装コストが大きい。
- 追加の圧縮方式: LZ4は実装済み。Windows向け方式は、必要な相互運用環境と
  性能目標が決まってから追加する。

実装済み
- 変更通知（File.WaitForChange）
- Kerberos認証（KerberosInitiator）
- バイト範囲ロック（File.Lock／File.Unlock）
- ACL・所有者の取得／設定（SecurityDescriptor API）
- 複合リクエスト
- 同一共有内のサーバー側コピー
- SMB3暗号化（AES-128-GCM／AES-128-CCM）
- LZ4圧縮
- io/fs対応
