## 1.1 Glossary

This document uses the following terms:

> <span id="gt_d2302116-d3d3-4465-a72e-c07a7737b7ae"
> class="anchor"></span>**8.3 name**: A file name string restricted in
> length to 12 characters that includes a base name of up to eight
> characters, one character for a period, and up to three characters for
> a file name extension. For more information on 8.3 file names, see
> [\[MS-CIFS\]](%5bMS-CIFS%5d.pdf#Section_d416ff7cc536406ea9514f04b2fd1d2b)
> section 2.2.1.1.1.
>
> <span id="gt_9f92aa05-dd0a-45f2-88d6-89f1fb654395"
> class="anchor"></span>**access control list (ACL)**: A list of access
> control entries (ACEs) that collectively describe the security rules
> for authorizing access to some resource; for example, an object or set
> of objects.
>
> <span id="gt_8b745eca-dc27-4455-a35d-bedef9fa29e7"
> class="anchor"></span>**alternate name**: An [**8.3
> name**](#gt_d2302116-d3d3-4465-a72e-c07a7737b7ae) that can optionally
> be generated when a file is created. A file will not have an
> [**alternate name**](#gt_8b745eca-dc27-4455-a35d-bedef9fa29e7) if the
> user wants to optimize performance, or if the name of the file already
> uses the 8.3 format.
>
> <span id="gt_ad861812-8cb0-497a-80bb-13c95aa4e425"
> class="anchor"></span>**binary large object (BLOB)**: A collection of
> binary data stored as a single entity in a database.
>
> <span id="gt_6c1aef9a-ae5a-4c85-ac7c-84da5eaacbab"
> class="anchor"></span>**chunk**: The amount of data that the operating
> system's implementation of the Lempel-Ziv compression algorithm tries
> to compress at one time. The [**compression
> unit**](#gt_ce0d64e7-0847-4910-9611-b3044f3aae2d) size used by the
> file system is always a multiple of the underlying compression
> algorithm's chunk size. For more information on the Lempel-Ziv
> compression algorithm, see \[UASDC\].
>
> <span id="gt_feef37b3-c173-4f51-aab6-b55a6366259b"
> class="anchor"></span>**cluster**: The smallest allocation unit on a
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c).
>
> <span id="gt_ce0d64e7-0847-4910-9611-b3044f3aae2d"
> class="anchor"></span>**compression unit**: The amount of data that
> [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a) tries to compress
> at one time. Compression of large files is accomplished as a series of
> compressions of data blocks, each at the most compression unit bytes
> in size.
>
> <span id="gt_4259c4db-f267-4dfc-80a6-fa2306056a34"
> class="anchor"></span>**compression unit shift**: The number of bits
> by which to left-shift a 1 bit to arrive at the [**compression
> unit**](#gt_ce0d64e7-0847-4910-9611-b3044f3aae2d) size.
>
> <span id="gt_f83c4971-a0c2-41a5-af59-6fae035ecb4a"
> class="anchor"></span>**content indexing service**: A service that
> extracts content from files and constructs an indexed catalog to
> facilitate efficient and rapid searching.
>
> <span id="gt_82dfddec-0095-4f51-9b36-b6f5a0458e22"
> class="anchor"></span>**disk quota**: Maximum amount of data a user
> can store on a disk
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c).
>
> <span id="gt_5c3cacdf-4505-454f-a359-653e71415be0"
> class="anchor"></span>**Distributed Link Tracking (DLT)**: A protocol
> that enables client applications to track sources that have been sent
> to remote locations using remote procedure call (RPC) interfaces, and
> to maintain links to files. It exposes methods that belong to two
> interfaces, one of which exists on the server (trksvr) and the other
> on a workstation (trkwks).
>
> <span id="gt_d45f0f94-9d52-490d-a8c4-2366a8008cb7"
> class="anchor"></span>**dot directory name**: In a pathname, a
> directory name component of "." (single period) or ".." (two periods).
> For more details, see
> [\[MS-FSCC\]](%5bMS-FSCC%5d.pdf#Section_efbfe12773ad41409967ec6500e66d5e)
> section 2.1.5.1.
>
> <span id="gt_5173ca58-7cec-499e-ae5a-c07d81ff5676"
> class="anchor"></span>**FAT file system**: A file system used to
> organize and manage files. The [**file allocation table
> (FAT)**](#gt_f2bf797b-e733-4fb9-b5e5-7e122f4abbe0) is a data structure
> that the operating system creates when a
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c) is formatted by
> using [**FAT**](#gt_f2bf797b-e733-4fb9-b5e5-7e122f4abbe0) or FAT32
> file systems. The operating system stores information about each file
> in the [**FAT**](#gt_f2bf797b-e733-4fb9-b5e5-7e122f4abbe0) so that it
> can retrieve the file later.
>
> <span id="gt_ab858f4d-7f0c-474c-9697-50f0af92f766"
> class="anchor"></span>**Fid**: A 16-bit value that the Server Message
> Block (SMB) server uses to represent an opened file, named pipe,
> printer, or device. A
> [**Fid**](#gt_ab858f4d-7f0c-474c-9697-50f0af92f766) is returned by an
> SMB server in response to a client request to open or create a file,
> named pipe, printer, or device. The SMB server guarantees that the
> [**Fid**](#gt_ab858f4d-7f0c-474c-9697-50f0af92f766) value returned is
> unique for a given SMB connection until the SMB connection is closed,
> at which time the [**Fid**](#gt_ab858f4d-7f0c-474c-9697-50f0af92f766)
> value can be reused. The
> [**Fid**](#gt_ab858f4d-7f0c-474c-9697-50f0af92f766) is used by the SMB
> client in subsequent SMB commands to identify the opened file, named
> pipe, printer, or device.
>
> <span id="gt_f2bf797b-e733-4fb9-b5e5-7e122f4abbe0"
> class="anchor"></span>**file allocation table (FAT)**: A data
> structure that the operating system creates when a volume is formatted
> by using [**FAT**](#gt_f2bf797b-e733-4fb9-b5e5-7e122f4abbe0) or FAT32
> file systems. The operating system stores information about each file
> in the [**FAT**](#gt_f2bf797b-e733-4fb9-b5e5-7e122f4abbe0) so that it
> can retrieve the file later.
>
> <span id="gt_fbbda8a1-53a1-4637-b0c9-8d04616913d5"
> class="anchor"></span>**file name component**: The portion of a file
> name between path separator characters (or backslashes).
>
> <span id="gt_9fc9f85b-fef7-4658-ba27-f0e8f49d0d49"
> class="anchor"></span>**file record segment**: A record in the
> [**master file table**](#gt_d379ab3d-69a9-46b2-8927-423c5a0970f1) that
> contains attributes for a specific file on an
> [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a)
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c). The file
> record segment is always 1,024 bytes (1 kilobyte) in size.
>
> <span id="gt_fd067b59-38c3-4b13-9e3f-76d2089488c6"
> class="anchor"></span>**file stream**: See main stream and [**named
> stream**](#gt_03d3ec14-995b-486a-8938-e2a73f6de7e1).
>
> <span id="gt_4ffb96a7-5fad-488e-9438-b7707d2e4226"
> class="anchor"></span>**file system control (FSCTL)**: A command
> issued to a file system to alter or query the behavior of the file
> system and/or set or query metadata that is associated with a
> particular file or with the file system itself.
>
> <span id="gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda"
> class="anchor"></span>**filter**: Type of driver that is layered
> between the kernel and a base file system (such as
> [**FAT**](#gt_f2bf797b-e733-4fb9-b5e5-7e122f4abbe0) or
> [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a)) that receives
> I/O request packets on their way to and from the base file system. The
> term [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda) can refer
> to legacy filters or minifilters.
>
> <span id="gt_09f024eb-3598-47db-91e0-37c83b82bf68"
> class="anchor"></span>**filter manager**: A file system
> [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda) driver that
> simplifies the development of other file system
> [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda) drivers.
> Although it is possible to write a filter driver that manages other
> [**filters**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda), for the
> purposes of this document, the phrase [**filter
> manager**](#gt_09f024eb-3598-47db-91e0-37c83b82bf68) refers only to
> the file system [**filter
> manager**](#gt_09f024eb-3598-47db-91e0-37c83b82bf68), which is an
> operating system component. A
> [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda) driver
> developed to the [**filter
> manager**](#gt_09f024eb-3598-47db-91e0-37c83b82bf68) model is called a
> minifilter.
>
> <span id="gt_f49694cc-c350-462d-ab8e-816f0103c6c1"
> class="anchor"></span>**globally unique identifier (GUID)**: A term
> used interchangeably with universally unique identifier (UUID) in
> Microsoft protocol technical documents (TDs). Interchanging the usage
> of these terms does not imply or require a specific algorithm or
> mechanism to generate the value. Specifically, the use of this term
> does not imply or require that the algorithms described in
> [\[RFC4122\]](https://go.microsoft.com/fwlink/?LinkId=90460) or
> [\[C706\]](https://go.microsoft.com/fwlink/?LinkId=89824) have to be
> used for generating the GUID. See also universally unique identifier
> (UUID).
>
> <span id="gt_b330cb96-68e2-41be-a53f-cae98c2b5d32"
> class="anchor"></span>**GUIDString**: A
> [**GUID**](#gt_f49694cc-c350-462d-ab8e-816f0103c6c1) in the form of an
> ASCII or Unicode string, consisting of one group of 8 hexadecimal
> digits, followed by three groups of 4 hexadecimal digits each,
> followed by one group of 12 hexadecimal digits. It is the standard
> representation of a GUID, as described in \[RFC4122\] section 3. For
> example, "6B29FC40-CA47-1067-B31D-00DD010662DA". Unlike a curly braced
> GUID string, a GUIDString is not enclosed in braces.
>
> <span id="gt_09d6bc87-34ed-48e8-b4d4-962e90543462"
> class="anchor"></span>**I/O control (IOCTL)**: A command that is
> issued to a target file system or target device in order to query or
> alter the behavior of the target; or to query or alter the data and
> attributes that are associated with the target or the objects that are
> exposed by the target.
>
> <span id="gt_2791e303-305a-48a4-8e4c-2799d4e34189"
> class="anchor"></span>**independent software vendor (ISV)**: A company
> or organization that develops software solutions that can utilize this
> specification.
>
> <span id="gt_a33da7f8-78bf-41a4-a4c0-a1d4caafa456"
> class="anchor"></span>**logical cluster number (LCN)**: The cluster
> number relative to the beginning of the volume. The first cluster on a
> volume is zero (0).
>
> <span id="gt_f53fe4b9-8e1d-4366-9254-3c4f73269e78"
> class="anchor"></span>**mailslot**: A mechanism for one-way
> interprocess communications (IPC). For more information, see
> [\[MSLOT\]](https://go.microsoft.com/fwlink/?LinkId=90218) and
> [\[MS-MAIL\]](%5bMS-MAIL%5d.pdf#Section_8ea19aa46e5a4aedb6280b5cd75a1ab9).
>
> <span id="gt_d379ab3d-69a9-46b2-8927-423c5a0970f1"
> class="anchor"></span>**master file table (MFT)**: On an
> [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a)
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c), the MFT is a
> relational database that consists of rows of file records and columns
> of file attributes. It contains at least one entry for every file on
> an [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a)
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c), including the
> MFT itself. The MFT stores the information required to retrieve files
> from the [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a)
> partition.
>
> <span id="gt_1e8c5c1d-10a9-452c-ad88-16ae095461f1"
> class="anchor"></span>**master file table mirror (MFT2/MFTMirr)**: On
> an [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a)
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c), the MFT2 is a
> redundant copy of the first four (4) records of the
> [**MFT**](#gt_d379ab3d-69a9-46b2-8927-423c5a0970f1).
>
> <span id="gt_03d3ec14-995b-486a-8938-e2a73f6de7e1"
> class="anchor"></span>**named stream**: A place within a file in
> addition to the main stream where data is stored, or the data stored
> therein. File systems support a mode in which it is possible to open
> either the main stream of a file and/or to open a named stream. Named
> streams and the main stream each have different data than each other
> and can be read and written independently. Not all file systems
> support named streams. See also
> [**stream**](#gt_f3529cd8-50da-4f36-aa0b-66af455edbb6).
>
> <span id="gt_0334e0bd-2755-42f6-aeff-2d4a22bf4abf"
> class="anchor"></span>**NetBIOS name**: A 16-byte address that is used
> to identify a NetBIOS resource on the network. For more information,
> see [\[RFC1001\]](https://go.microsoft.com/fwlink/?LinkId=90260) and
> [\[RFC1002\]](https://go.microsoft.com/fwlink/?LinkId=90261).
>
> <span id="gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a"
> class="anchor"></span>**NT file system (NTFS)**: A proprietary
> Microsoft file system. For more information, see
> [\[MSFT-NTFS\]](https://go.microsoft.com/fwlink/?LinkId=90200).
>
> <span id="gt_2467c614-592b-4177-b82b-2d2d130752fc"
> class="anchor"></span>**Object ID**: See ObjectID.
>
> <span id="gt_aaaf2f1a-0b0a-487e-a0f0-c3510a6091b2"
> class="anchor"></span>**object identifier (OID)**: In the context of
> an object server, a 64-bit number that uniquely identifies an object.
>
> <span id="gt_fbc5b8e4-ba0b-497d-ab17-1cfc3f81554c"
> class="anchor"></span>**object-oriented file system**: In the context
> of file system control codes, a file system that allows the assignment
> of object IDs to files.
>
> <span id="gt_cce551b7-ef87-4cd1-ac7f-9d8d019cfbf3"
> class="anchor"></span>**Offload Read**: A variant to a normal read
> operation where a target device generates and returns a
> [**Token**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5) instead of a
> buffer containing the data to be read. The
> [**Token**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5) is maintained by
> the target device until it invalidates the
> [**Token**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5) for any
> vendor-specific reason. The data logically represented by the
> [**Token**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5) cannot change,
> and the target device is required to maintain this representation. An
> example of a target device is a SAN Storage Array with support for the
> associated low-level storage commands. For more information on
> [**Offload Read**](#gt_cce551b7-ef87-4cd1-ac7f-9d8d019cfbf3), see
> [\[INCITS-T10/11-059\]](https://go.microsoft.com/fwlink/?LinkId=239442).
>
> <span id="gt_4755684a-cd1e-4166-a8b4-c888912b2b01"
> class="anchor"></span>**Offload Write**: A variant to a normal write
> operation where the host provides a
> [**Token**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5) instead of a
> buffer containing the data to be written. Upon receipt of the
> [**Offload Write**](#gt_4755684a-cd1e-4166-a8b4-c888912b2b01), the
> target device parses the
> [**Token**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5) and determines
> whether the data movement (the Write) can be completed to the
> requested location. An example of a target device is a SAN Storage
> Array with support for the associated low-level storage commands. For
> more information on [**Offload
> Write**](#gt_4755684a-cd1e-4166-a8b4-c888912b2b01), see
> \[INCITS-T10/11-059\].
>
> <span id="gt_4fed0b53-5fc8-4818-886f-93d87f3035e1"
> class="anchor"></span>**reparse point**: An attribute that can be
> added to a file to store a collection of user-defined data that is
> opaque to [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a) or
> ReFS. If a file that has a reparse point is opened, the open will
> normally fail with STATUS_REPARSE, so that the relevant file system
> [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda) driver can
> detect the open of a file associated with (owned by) this reparse
> point. At that point, each installed
> [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda) driver can
> check to see if it is the owner of the reparse point, and, if so,
> perform any special processing required for a file with that reparse
> point. The format of this data is understood by the application that
> stores the data and the file system
> [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda) that interprets
> the data and processes the file. For example, an encryption
> [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda) that is marked
> as the owner of a file's reparse point could look up the encryption
> key for that file. A file can have (at most) 1 reparse point
> associated with it. For more information, see \[MS-FSCC\].
>
> <span id="gt_0be8a9c1-34d6-4632-b430-c5cf4ecc38a7"
> class="anchor"></span>**reparse point tag**: A unique identifier for a
> file system [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda)
> driver stored within a file's optional [**reparse
> point**](#gt_4fed0b53-5fc8-4818-886f-93d87f3035e1) data that indicates
> the file system [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda)
> driver that performs additional filter-defined processing on a file
> during I/O operations. An implementer can request more than one
> [**reparse point**](#gt_4fed0b53-5fc8-4818-886f-93d87f3035e1) for use
> with a file system, a file system
> [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda) driver, or a
> minifilter driver. To request a reparse point tag, use the reparse
> point tag request form. For more information, see
> [\[WHDC-RPTR\]](https://go.microsoft.com/fwlink/?LinkId=90564).
>
> <span id="gt_6cef9d9c-c366-490a-8e4e-a350688731ca"
> class="anchor"></span>**replica set**: In File Replication Service
> (FRS), the replication of files and directories according to a
> predefined topology and schedule on a specific folder. The topology
> and schedule are collectively called a replica set. A replica set
> contains a set of replicas, one for each machine that participates in
> replication.
>
> <span id="gt_b5bbe646-aa5f-4b4e-ae9e-bdae444cbfa2"
> class="anchor"></span>**sector**: The smallest addressable unit of a
> disk.
>
> <span id="gt_83f2020d-0804-4840-a5ac-e06439d50f8d"
> class="anchor"></span>**security identifier (SID)**: An identifier for
> security principals that is used to identify an account or a group.
> Conceptually, the [**SID**](#gt_83f2020d-0804-4840-a5ac-e06439d50f8d)
> is composed of an account authority portion (typically a domain) and a
> smaller integer representing an identity relative to the account
> authority, termed the relative identifier (RID). The
> [**SID**](#gt_83f2020d-0804-4840-a5ac-e06439d50f8d) format is
> specified in
> [\[MS-DTYP\]](%5bMS-DTYP%5d.pdf#Section_cca2742956894a16b2b49325d93e4ba2)
> section 2.4.2; a string representation of
> [**SIDs**](#gt_83f2020d-0804-4840-a5ac-e06439d50f8d) is specified in
> \[MS-DTYP\] section 2.4.2 and
> [\[MS-AZOD\]](%5bMS-AZOD%5d.pdf#Section_5a0a0a3ec7a742e1b5f2cc8d8bd9739e)
> section 1.1.1.2.
>
> <span id="gt_0e05d13e-4bda-44f7-8650-e1c1b53cca17"
> class="anchor"></span>**short name**: This has the same definition as
> [**alternate name**](#gt_8b745eca-dc27-4455-a35d-bedef9fa29e7).
>
> <span id="gt_40c57198-06d7-4dcb-a011-d8152b64d2cb"
> class="anchor"></span>**single-instance storage (SIS)**: An
> [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a) feature that
> implements links with the semantics of copies for files stored on an
> [**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a)
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c).
> [**SIS**](#gt_40c57198-06d7-4dcb-a011-d8152b64d2cb) uses copy-on-close
> to implement the copy semantics of its links.
>
> <span id="gt_57c7faf0-6002-4b1a-b8fc-fc9244d5a6e5"
> class="anchor"></span>**sparse file**: A file containing large
> sections of data composed only of zeros. This file is marked as a
> sparse file in the file system, which saves disk space by only
> allocating as many ranges on disk as are required to completely
> reconstruct the non-zero data. When an attempt is made to read in the
> nonallocated portions of the file (also known as holes), the file
> system automatically returns zeros to the caller.
>
> <span id="gt_f3529cd8-50da-4f36-aa0b-66af455edbb6"
> class="anchor"></span>**stream**: A sequence of bytes written to a
> file on the target file system. Every file stored on a
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c) that uses the
> file system contains at least one stream, which is normally used to
> store the primary contents of the file. Additional streams within the
> file can be used to store file attributes, application parameters, or
> other information specific to that file. Every file has a default data
> stream, which is unnamed by default. That data stream, and any other
> data stream associated with a file, can optionally be named.
>
> <span id="gt_ec3f0097-f724-412e-baa2-d2341dbd6bce"
> class="anchor"></span>**sub-read and sub-write**: An I/O operation
> sent by the file system to the storage stack that is part of a larger
> file I/O operation. Sometimes large file reads and writes are broken
> down by the file system into smaller reads and writes, which are then
> sent to the storage stack.
>
> <span id="gt_04f1ed93-15cb-4090-8204-c43bec8c7398"
> class="anchor"></span>**symbolic link**: A [**symbolic
> link**](#gt_04f1ed93-15cb-4090-8204-c43bec8c7398) is a [**reparse
> point**](#gt_4fed0b53-5fc8-4818-886f-93d87f3035e1) that points to
> another file system object. The object being pointed to is called the
> target. [**Symbolic links**](#gt_04f1ed93-15cb-4090-8204-c43bec8c7398)
> are transparent to users; the links appear as normal files or
> directories, and can be acted upon by the user or application in
> exactly the same manner. [**Symbolic
> links**](#gt_04f1ed93-15cb-4090-8204-c43bec8c7398) can be created
> using the FSCTL_SET_REPARSE_POINT request as specified in \[MS-FSCC\]
> section 2.3.81. They can be deleted using the
> FSCTL_DELETE_REPARSE_POINT request as specified in \[MS-FSCC\] section
> 2.3.5. Implementing [**symbolic
> links**](#gt_04f1ed93-15cb-4090-8204-c43bec8c7398) is optional for a
> file system.
>
> <span id="gt_bfa52023-7248-4ab5-b889-6b53348a773b"
> class="anchor"></span>**tag**: Another name for a [**reparse
> point**](#gt_4fed0b53-5fc8-4818-886f-93d87f3035e1). For instance, the
> file system [**filter
> manager**](#gt_09f024eb-3598-47db-91e0-37c83b82bf68) FltTagFile
> routine sets a [**reparse
> point**](#gt_4fed0b53-5fc8-4818-886f-93d87f3035e1) on a file. Tag is
> also used to refer to the field in a [**reparse
> point**](#gt_4fed0b53-5fc8-4818-886f-93d87f3035e1) that identifies
> what software component put the [**reparse
> point**](#gt_4fed0b53-5fc8-4818-886f-93d87f3035e1) there.
>
> <span id="gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5"
> class="anchor"></span>**token**: A 512-byte length opaque string that
> is generated and maintained by a supported target device. A
> [**Token**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5) functions
> logically as an immutable point-in-time representation for a set of
> data specified by a host and can be conceptualized as a compressed
> representation of the data that only a certain class of storage
> subsystems can interpret. A
> [**Token**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5) can also be
> constructed from a set of well-known
> [**Tokens**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5) to enable the
> client to describe a homogeneous attribute for a set of data (for
> example, all zeros) or to enable a server to apply a homogeneous
> attribute to a set of data (for example, a set of all zeros). For more
> information on [**Tokens**](#gt_95f17071-c8f1-403a-8a92-cf87aa7d40f5),
> see \[INCITS-T10/11-059\].
>
> <span id="gt_fd33af2e-e1ce-4f8e-a706-f9fb8123f9b0"
> class="anchor"></span>**Unicode character**: Unless otherwise
> specified, a 16-bit UTF-16 code unit.
>
> <span id="gt_433a4fb7-ef84-46b0-ab65-905f5e3a80b1"
> class="anchor"></span>**Uniform Resource Locator (URL)**: A string of
> characters in a standardized format that identifies a document or
> resource on the World Wide Web. The format is as specified in
> [\[RFC1738\]](https://go.microsoft.com/fwlink/?LinkId=90287).
>
> <span id="gt_cb5a1da2-5cc8-4e3f-80b9-32d55c5ca95f"
> class="anchor"></span>**Universal Disk Format (UDF)**: A type of file
> system for storing files on optical media.
>
> <span id="gt_01936446-8739-4b98-b83f-fb5e2a53ce4c"
> class="anchor"></span>**update sequence number (USN)**: The offset
> from the beginning of the change journal stream that uniquely
> identifies a change journal record.
>
> <span id="gt_a80257f7-33b1-45d6-aafc-36ecdd5e11ae"
> class="anchor"></span>**virtual cluster number (VCN)**: The cluster
> number relative to the beginning of the file, directory, or
> [**stream**](#gt_f3529cd8-50da-4f36-aa0b-66af455edbb6) within a file.
> The [**cluster**](#gt_feef37b3-c173-4f51-aab6-b55a6366259b) describing
> byte 0 in a file is VCN 0.
>
> <span id="gt_9a876829-33a1-4f0b-8b81-8552b7e5561c"
> class="anchor"></span>**volume**: A group of one or more partitions
> that forms a logical region of storage and the basis for a file
> system. A [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c) is an
> area on a storage device that is managed by the file system as a
> discrete logical storage unit. A partition contains at least one
> [**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c), and a volume
> can exist on one or more partitions.
>
> **MAY, SHOULD, MUST, SHOULD NOT, MUST NOT:** These terms (in all caps)
> are used as defined in
> [\[RFC2119\]](https://go.microsoft.com/fwlink/?LinkId=90317). All
> statements of optional behavior use either MAY, SHOULD, or SHOULD NOT.
