### 2.3.39 FSCTL_MARK_HANDLE Request

The FSCTL_MARK_HANDLE request is used to set specific operational state
on the given file handle. This state is lost once the handle is
closed.<span id="Appendix_A_Target_35"
class="anchor"></span>[\<35\>](#Appendix_A_35)

**CopyNumber (4 bytes)**: A 32-bit unsigned integer that identifies,
when reading from a file which resides on redundant media, which copy to
read.

**Unused (4 bytes):** Reserved for alignment. This field can contain any
value and MUST be ignored.

**VolumeHandle (8 bytes):** A 64-bit HANDLE that is not used and MUST be
set to zero.

**HandleInfo (4 bytes):** A 32-bit unsigned integer containing flags to
identify the request. Only one of the following values can be set:

<td><p>MARK_HANDLE_READ_COPY</p>
<p>0x00000080</p></td>
<td><p>When a file resides on redundant media (ex: mirrored or RAID)
this tells the file system that read operations on this handle should
only come from the specified copy of data.</p>
<p>When this state is not set a file system will return data from any
copy available as it sees fit.</p>
<p>This operation is typically used by scrubber applications that want
to validate the contents of all copies of data for a given
file.</p></td>
</tr>
<tr>
<td><p>MARK_HANDLE_NOT_READ_COPY</p>
<p>0x00000100</p></td>
<td>When a file resides on redundant media (ex: mirrored or RAID) this
tells the file system that read operations on this handle may come from
any copy of the data as the file system sees fit. This turns off reading
from a specific copy.</td>
</tr>

**Reserved (4 Bytes):** A 32-bit field. This field is reserved. This
field SHOULD be set to 0, and MUST be ignored.
