### 2.3.28 FSCTL_GET_REPARSE_POINT Reply

This message returns the results of the [FSCTL_GET_REPARSE_POINT
request](#Section_b68d9eda15d24edea94d58a81f331429). The message
contains a
[REPARSE_GUID_DATA_BUFFER](#Section_a4d083740e9243e28f8888b94112f070)
(including subtypes) or a
[REPARSE_DATA_BUFFER](#Section_c3a420cb8a724adf87e8eee95379d78f) data
element.

Both the REPARSE_GUID_DATA_BUFFER and the REPARSE_DATA_BUFFER structures
begin with a **ReparseTag** field. The ReparseTag value uniquely
identifies the [**filter**](#gt_ffbe7b55-8e84-4f41-a18d-fc29191a4cda)
driver that creates/uses the [**reparse
point**](#gt_4fed0b53-5fc8-4818-886f-93d87f3035e1), and the
application's filter driver processes the reparse point data as either a
REPARSE_GUID_DATA_BUFFER or a REPARSE_DATA_BUFFER, depending on the
structure implemented by the filter driver for that type of reparse
point. A particular filter driver is implemented with specific support
for the type of reparse point data structure it accepts.

If the file system of the
[**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c) containing the
specified file or directory does not support the use of reparse points,
the request will not succeed. The error code returned in this situation
MAY vary, depending on the file system.<span id="Appendix_A_Target_29"
class="anchor"></span>[\<29\>](#Appendix_A_29)

This message also returns a status code as specified in section
[2.2](#Section_a7527db8cbfe4f2aabc3133bf5160bd7). Upon success, the
status code returned by the function that processes this
[**FSCTL**](#gt_4ffb96a7-5fad-488e-9438-b7707d2e4226) is STATUS_SUCCESS.
