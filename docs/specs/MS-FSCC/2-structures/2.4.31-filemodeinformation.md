### 2.4.31 FileModeInformation

The **FileModeInformation** information class is used to query or set
the mode of the file. The mode returned by a query corresponds to the
**CreateOptions** used in the initial create operation, modified by any
set FileModeInformation operations performed since the create
operation.<span id="Appendix_A_Target_135"
class="anchor"></span>[\<135\>](#Appendix_A_135)

A **FILE_MODE_INFORMATION** data element, defined as follows, is
returned by the server or provided by the client.

**Mode (4 bytes):** A 32-bit unsigned integer that specifies how the
file will subsequently be accessed.

<table style="width:96%;">
<colgroup>
<col style="width: 35%" />
<col style="width: 60%" />
</colgroup>
<thead>
<tr>
<th>Value</th>
<th>Meaning</th>
</tr>
</thead>
<tbody>
<tr>
<td><p>FILE_WRITE_THROUGH</p>
<p>0x00000002</p></td>
<td>When set, any system services, file system drivers (FSDs), and
drivers that write data to the file are required to actually transfer
the data into the file before any requested write operation is
considered complete.</td>
</tr>
<tr>
<td><p>FILE_SEQUENTIAL_ONLY</p>
<p>0x00000004</p></td>
<td>This is a hint that informs the cache that it SHOULD<span
id="Appendix_A_Target_136" class="anchor"></span><a
href="#Appendix_A_136">&lt;136&gt;</a> optimize for sequential access.
Non-sequential access of the file can result in performance
degradation.</td>
</tr>
<tr>
<td><p>FILE_NO_INTERMEDIATE_BUFFERING</p>
<p>0x00000008</p></td>
<td>When set, the file cannot be cached or buffered in a driver's
internal buffers.</td>
</tr>
<tr>
<td><p>FILE_SYNCHRONOUS_IO_ALERT</p>
<p>0x00000010</p></td>
<td>When set, all operations on the file are performed synchronously.
Any wait on behalf of the caller is subject to premature termination
from alerts. This flag also causes the I/O system to maintain the file
position context.</td>
</tr>
<tr>
<td><p>FILE_SYNCHRONOUS_IO_NONALERT</p>
<p>0x00000020</p></td>
<td>When set, all operations on the file are performed synchronously.
Wait requests in the system to synchronize I/O queuing and completion
are not subject to alerts. This flag also causes the I/O system to
maintain the file position context.</td>
</tr>
<tr>
<td><p>FILE_DELETE_ON_CLOSE</p>
<p>0x00001000</p></td>
<td>This flag is not implemented and is always returned as not set.</td>
</tr>
</tbody>
</table>

This operation returns a status code as specified in section
[2.2](#Section_a7527db8cbfe4f2aabc3133bf5160bd7). Upon success, the
status code returned by the function that processes this file
information class is STATUS_SUCCESS. The most common error codes are
listed in the following table.

<td><p>STATUS_INFO_LENGTH_MISMATCH</p>
<p>0xC0000004</p></td>
<td>The specified information record length does not match the length
that is required for the specified information class.</td>
</tr>
<tr>
<td>STATUS_INVALID_PARAMETER</td>
<td><p>An attempt to set the file mode returns STATUS_INVALID_PARAMETER
in any of the following cases:</p>
<ul>
<li><p>The <strong>Mode</strong> field contains any flag other than
FILE_WRITE_THROUGH, FILE_SEQUENTIAL_ONLY, FILE_SYNCHRONOUS_IO_ALERT, or
FILE_SYNCHRONOUS_IO_NONALERT.</p></li>
<li><p>FILE_SYNCHRONOUS_IO_ALERT or FILE_SYNCHRONOUS_IO_NONALERT is set
and the file was not opened for synchronous I/O.</p></li>
<li><p>Neither FILE_SYNCHRONOUS_IO_ALERT nor
FILE_SYNCHRONOUS_IO_NONALERT are set and the file was opened for
synchronous I/O.</p></li>
<li><p>FILE_SYNCHRONOUS_IO_ALERT and FILE_SYNCHRONOUS_IO_NONALERT are
both set.</p></li>
</ul></td>
</tr>
