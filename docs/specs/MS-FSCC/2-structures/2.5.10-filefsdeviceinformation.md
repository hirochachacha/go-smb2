### 2.5.10 FileFsDeviceInformation

This information class is used to query device information associated
with a file system
[**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c).

**DeviceType (4 bytes):** This identifies the type of given volume. It
MUST be one of the following.

<table style="width:51%;">
<colgroup>
<col style="width: 22%" />
<col style="width: 28%" />
</colgroup>
<thead>
<tr>
<th>Value</th>
<th>Meaning</th>
</tr>
</thead>
<tbody>
<tr>
<td><p>FILE_DEVICE_CD_ROM</p>
<p>0x00000002</p></td>
<td>Volume resides on a CD ROM.</td>
</tr>
<tr>
<td><p>FILE_DEVICE_DISK</p>
<p>0x00000007</p></td>
<td>Volume resides on a disk.</td>
</tr>
</tbody>
</table>

**Characteristics (4 bytes):** A bit field which identifies various
characteristics about a given volume. The following are valid bit
values.

<table style="width:97%;">
<colgroup>
<col style="width: 47%" />
<col style="width: 49%" />
</colgroup>
<thead>
<tr>
<th>Value</th>
<th>Meaning</th>
</tr>
</thead>
<tbody>
<tr>
<td><p>FILE_REMOVABLE_MEDIA</p>
<p>0x00000001</p></td>
<td>Indicates that the storage device supports removable media. Notice
that this characteristic indicates removable media, not a removable
device. For example, drivers for JAZ drive devices specify this
characteristic, but drivers for PCMCIA flash disks do not.</td>
</tr>
<tr>
<td><p>FILE_READ_ONLY_DEVICE</p>
<p>0x00000002</p></td>
<td>Indicates that the device cannot be written to.</td>
</tr>
<tr>
<td><p>FILE_FLOPPY_DISKETTE</p>
<p>0x00000004</p></td>
<td>Indicates that the device is a floppy disk device.</td>
</tr>
<tr>
<td><p>FILE_WRITE_ONCE_MEDIA</p>
<p>0x00000008</p></td>
<td>Indicates that the device supports write-once media.</td>
</tr>
<tr>
<td><p>FILE_REMOTE_DEVICE</p>
<p>0x00000010</p></td>
<td>Indicates that the volume is for a remote file system like SMB or
CIFS.</td>
</tr>
<tr>
<td><p>FILE_DEVICE_IS_MOUNTED</p>
<p>0x00000020</p></td>
<td>Indicates that a file system is mounted on the device.</td>
</tr>
<tr>
<td><p>FILE_VIRTUAL_VOLUME</p>
<p>0x00000040</p></td>
<td>Indicates that the volume does not directly reside on storage media
but resides on some other type of media (memory for example).</td>
</tr>
<tr>
<td><p>FILE_DEVICE_SECURE_OPEN</p>
<p>0x00000100</p></td>
<td>By default, volumes do not check the ACL associated with the volume,
but instead use the ACLs associated with individual files on the volume.
When this flag is set the volume ACL is also checked.</td>
</tr>
<tr>
<td><p>FILE_CHARACTERISTIC_TS_DEVICE</p>
<p>0x00001000</p></td>
<td>Indicates that the device object is part of a Terminal Services
device stack. See <a
href="%5bMS-RDPBCGR%5d.pdf#Section_5073f4ed1e9345e1b0396e30c385867c">[MS-RDPBCGR]</a>
for more information.</td>
</tr>
<tr>
<td><p>FILE_CHARACTERISTIC_WEBDAV_DEVICE</p>
<p>0x00002000</p></td>
<td>Indicates that a web-based Distributed Authoring and Versioning
(WebDAV) file system is mounted on the device. See <a
href="%5bMS-WDVME%5d.pdf#Section_8cafdf55ee5c443ebdb72cb2ab1fb2c3">[MS-WDVME]</a>
for more information.</td>
</tr>
<tr>
<td><p>FILE_DEVICE_ALLOW_APPCONTAINER_TRAVERSAL</p>
<p>0x00020000</p></td>
<td>The IO Manager normally performs a full security check for traverse
access on every file open when the client is an appcontainer. Setting of
this flag bypasses this enforced traverse access check if the client
token already has traverse privileges.<span id="Appendix_A_Target_186"
class="anchor"></span><a href="#Appendix_A_186">&lt;186&gt;</a></td>
</tr>
<tr>
<td><p>FILE_PORTABLE_DEVICE</p>
<p>0x0004000</p></td>
<td>Indicates that the given device resides on a portable bus like USB
or Firewire and that the entire device (not just the media) can be
removed from the system.</td>
</tr>
</tbody>
</table>

[2.2](#Section_a7527db8cbfe4f2aabc3133bf5160bd7). Upon success, the
status code returned by the function that processes this file system
information class is STATUS_SUCCESS. The most common error codes are
listed in the following table.
