### 2.3.79 FSCTL_SET_OBJECT_ID_EXTENDED Request

The FSCTL_SET_OBJECT_ID_EXTENDED request message requests that the
server set the extended information for the file or directory associated
with the handle on which this
[**FSCTL**](#gt_4ffb96a7-5fad-488e-9438-b7707d2e4226) was invoked. The
message contains an EXTENDED_INFO data element.

The EXTENDED_INFO data element is defined as follows.

**ExtendedInfo (48 bytes):** A 48-byte binary large object(BLOB)
containing user-defined extended data that was passed to this FSCTL by
an application. In this situation, the user refers to the implementer
who is calling this FSCTL, meaning the extended info is opaque to
[**NTFS**](#gt_86f79a17-c0be-4937-8660-0cf6ce5ddc1a); there are no rules
enforced by NTFS as to what these last 48 bytes contain. Contrast this
with the first 16 bytes of an object ID, which can be used to open the
file, so NTFS requires that they be unique within a
[**volume**](#gt_9a876829-33a1-4f0b-8b81-8552b7e5561c).<span id="Appendix_A_Target_79"
