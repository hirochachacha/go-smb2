**Flags (4 bytes):** A 32-bit field that specifies options on how the
file is deleted.

This field contains one or more of the values in the following table.

<table style="width:98%;">
<colgroup>
<col style="width: 48%" />
<col style="width: 48%" />
</colgroup>
<thead>
<tr>
<th>Value</th>
<th>Meaning</th>
</tr>
</thead>
<tbody>
<tr>
<td><p>FILE_DISPOSITION_DO_NOT_DELETE_FILE</p>
<p>0x00000000</p></td>
<td>If no flag is set, the file MUST NOT be deleted.</td>
</tr>
<tr>
<td><p>FILE_DISPOSITION_DELETE</p>
<p>0x00000001</p></td>
<td>If set, indicates the file SHOULD be deleted.</td>
</tr>
<tr>
<td><p>FILE_DISPOSITION_POSIX_SEMANTICS</p>
<p>0x00000002</p></td>
<td>If set and FILE_DISPOSITION_DELETE is set, indicates the file SHOULD
be deleted using POSIX-style semantics. This means the link is removed
from the visible namespace as soon as the POSIX delete handle is closed,
but the file's data streams remain accessible by other existing
handles.</td>
</tr>
<tr>
<td><p>FILE_DISPOSITION_FORCE_IMAGE_SECTION_CHECK</p>
<p>0x00000004</p></td>
<td>If set, indicates the system SHOULD fail deleting the file if an
image section exists. If not set and the
FILE_DISPOSITION_POSIX_SEMANTICS flag is set; indicates the file can be
deleted even if it has an image section. This flag was added to support
backward compatibility with the existing behavior of the
FileDispositionInformation (see section <a
href="#Section_12c3dd1c14f642299d2975fb2cb392f6">2.4.11</a>)
operation.</td>
</tr>
<tr>
<td><p>FILE_DISPOSITION_ON_CLOSE</p>
<p>0x00000008</p></td>
<td><p>If set and the FILE_DISPOSITION_POSIX_SEMANTICS flag is set; the
file FILE_DELETE_ON_CLOSE state is updated to specify POSIX-style delete
semantics.</p>
<p>If set and the FILE_DISPOSITION_POSIX_SEMANTICS flag is
<strong>not</strong> set; the file FILE_DELETE_ON_CLOSE state is updated
to <strong>not</strong> specify POSIX-style delete semantics.</p>
<p>If set and the file is not opened with FILE_DELETE_ON_CLOSE,
STATUS_NOT_SUPPORTED MUST be returned.</p></td>
</tr>
<tr>
<td><p>FILE_DISPOSITION_IGNORE_READONLY_ATTRIBUTE</p>
<p>0x00000010</p></td>
<td>If set, allows files with the READ_ONLY attribute to be deleted
anyway. Without this flag, deleting a read-only file MUST return
STATUS_CANNOT_DELETE.</td>
</tr>
</tbody>
</table>

This operation returns a status code as specified in section
[2.2](#Section_a7527db8cbfe4f2aabc3133bf5160bd7). Upon success, the
status code returned by the function that processes this file
information class is STATUS_SUCCESS. The most common error codes are
listed in the following table.

<p>0xC0000022</p></td>
<td>The handle was not opened with delete access.</td>
</tr>
<tr>
<td><p>STATUS_INFO_LENGTH_MISMATCH</p>
<p>0xC0000004</p></td>
<td>The specified information record length does not match the length
